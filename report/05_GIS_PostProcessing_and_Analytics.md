# 05 - GIS Post-Processing, Clustering, and Analytics

Raw pixel-level predictions from deep learning models are insufficient for policy analysis or environmental modeling. Because inference is executed via overlapping sliding windows on massive GeoTIFFs, the raw output contains significant duplication and artifacting. The `postprocess.py`, `gis.py`, and `analytics.py` modules refine these predictions into standardized, actionable GIS artifacts.

## 1. Spatial Deduplication
When a large, 500-foot poultry house spans across multiple strided image tiles, the YOLO model evaluates it multiple times, yielding multiple overlapping detections. Two suppression techniques are utilized to resolve this:

### Centroid Suppression
For bounding boxes, the pipeline computes the geographic center (centroid) of every detection. If multiple centroids fall within a highly restrictive geographic radius (e.g., 5 meters), the algorithm flags them as referring to the same physical structure. The detection with the highest confidence score is preserved, and the duplicates are suppressed.

### Mask Non-Maximum Suppression (NMS)
For segmentation masks, evaluating centroids is insufficient. The pipeline utilizes the actual geometry of the polygons, computing the Intersection-over-Union (IoU) of overlapping shapes. If two predicted roofs overlap by more than a specified threshold (e.g., `iou-threshold 0.5`), the geometries are merged (dissolved) into a single, unified polygon, perfectly tracing the entire continuous roofline.

## 2. Farm Entity Clustering
Environmental impact is rarely dictated by a single barn; poultry operations typically consist of densely packed, parallel arrays of 4 to 12 houses. To accurately quantify agricultural density, individual house detections must be grouped into unified "Farm" entities.

### DBSCAN Spatial Clustering
The `cluster-farms` command applies DBSCAN (Density-Based Spatial Clustering of Applications with Noise) to the deduplicated house centroids.
- **Mechanism:** Using domain-specific parameters (e.g., `--eps-house 50.0` meters and `--min-samples 2`), the algorithm scans the geographic landscape. Proximal houses are mathematically bound together.
- **Output:** The algorithm assigns a unified "Farm ID" to the grouped houses and generates a macro-centroid representing the entire operation.

## 3. GIS Vector Export
To interface with external stakeholders and traditional GIS software (ArcGIS, QGIS), pandas DataFrames are converted to standardized vector formats.

### Reprojection
All coordinate data generated from the imagery is re-projected on the fly to a localized, metrical Coordinate Reference System (e.g., `EPSG:26916` for the Southeastern US). This is critical: using raw degrees of latitude/longitude results in distorted area calculations. Metrical projection ensures measurements are strictly accurate in square meters.

### Artifact Generation
- **ESRI Shapefiles:** Detections are natively exported as point features (centroids), bounding boxes, or precise polygonal outlines.
- **KML Output:** The `csv-to-kml` command generates Keyhole Markup Language files, allowing detection boundaries and farm clusters to be effortlessly overlaid and verified within Google Earth.

## 4. County-Level Environmental Analytics
The ultimate objective of the pipeline is environmental screening—specifically, assessing the potential volume of contaminated rainfall runoff entering local watersheds.

### Aggregation and Mask Geometry
The pipeline spatially intersects the locations of detected farms with official county boundary shapefiles. Utilizing the highly accurate polygon masks generated by the YOLO segmentation model, the module calculates the exact geometric surface area of the impervious poultry roofs.

### Runoff Estimation and Correction
- **Calculations:** The total square meterage of the roofs is cross-referenced with historical, localized precipitation datasets to calculate the estimated volume of rainfall striking the operations.
- **NASS Correction via Bootstrapping:** Deep learning predictions possess a margin of error (false positives/negatives). To ensure policy-grade accuracy, the `analytics.py` module applies statistical bootstrapping to the output data, mathematically correcting the predicted farm counts against official, ground-truth agricultural census baselines provided by the National Agricultural Statistics Service (NASS).

## 5. NAIP Detection Script — Standalone Geospatial Inference

For batch inference on raw NAIP GeoTIFF archives (such as the GA 60cm imagery in `E:\Test`), the standalone script `scripts/run_naip_detection.py` provides a fully self-contained, config-driven detection pipeline without SAM or segmentation:

### Detection Pipeline
1. **Tile-based sliding window:** Each large GeoTIFF (10,710 × 12,300 px, ~500 MB) is decomposed into overlapping 1024 × 1024 px tiles with configurable overlap (default 20%).
2. **YOLO11l inference:** Tiles are batch-fed to YOLO11l (COCO-pretrained or fine-tuned) at batch_size=8 on CUDA.
3. **Cross-tile NMS:** After inference, all raw detections from all tiles are pooled and global NMS (IoU=0.40) removes duplicate detections that span tile boundaries.
4. **Coordinate reprojection:** Each bounding box centroid and corner is reprojected via `pyproj` to the target CRS.

### Coordinate Reference Systems
The script handles the multi-CRS character of the Georgia NAIP dataset automatically:

| Layer | EPSG | Units | Notes |
|---|---|---|---|
| Source (NAIP `E:\Test`) | **26917** | meters | NAD83 / UTM Zone 17N |
| Primary output | **6444** | US survey ft | NAD83(2011) / Georgia East State Plane |
| Supplementary | **4326** | decimal degrees | WGS-84 lat/lon |

### Output CSV Columns
Every detected object is described by 25+ columns covering pixel-space bounding boxes, source-CRS native coordinates, State Plane Easting/Northing, WGS-84 lat/lon, detection confidence, class ID, and source tile metadata. See [`reports/naip_detection_guide.md`](../reports/naip_detection_guide.md) for the full schema.

### Usage
```powershell
# Run all 30 E:\Test images with defaults
.\.venv\Scripts\python.exe scripts\run_naip_detection.py --config configs\detect_naip_config.yaml

# Override CRS for files spanning the GA West zone
.\.venv\Scripts\python.exe scripts\run_naip_detection.py `
    --config configs\detect_naip_config.yaml `
    --target-crs EPSG:6445
```
